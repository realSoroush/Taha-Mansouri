# طاها منصوری — نسخه 0.1.0

نمونهٔ فرانت‌اند لندینگ فارسی با React، Vite و TypeScript. مناسب GitHub Codespaces و Vercel.

## اجرای پروژه

Node.js نسخهٔ ۲۲ یا بالاتر:

```bash
npm ci
npm run dev
```

در Codespaces از تب **Ports** پورت `4173` را در مرورگر باز کنید. تغییر متن‌ها بلافاصله در پیش‌نمایش ظاهر می‌شود.

```bash
npm run build
```

این دستور TypeScript را بررسی کرده و خروجی انتشار را در `dist` می‌سازد.

## ویرایش محتوا در جلسه

تمام متن‌های صفحه، شماره‌ها و مسیر عکس‌ها در **`src/content.ts`** قرار دارند:

| کلید | بخش |
|---|---|
| `brand` | نام و عنوان طاها |
| `hero` | تیتر اصلی، معرفی کوتاه، عکس اصلی |
| `services.items` | کارت‌های خدمات |
| `audience` | مخاطبان |
| `process` | مراحل همکاری و سه جلسه رایگان |
| `about` | معرفی طاها و تیم |
| `work.items` | نمونه‌کارها و تصاویر |
| `education` | وضعیت دوره‌های آینده |
| `contact` | تماس، واتساپ و تلگرام |
| `footer` | پایین صفحه |

متن داخل `'...'` را عوض کنید. ویرگول‌ها و آکولادها را حذف نکنید. برای گیومه داخل متن فارسی، از «» استفاده کنید. در صورت تغییر تعداد کارت‌ها یا ساختار داده، build را دوباره بررسی کنید.

### افزودن عکس

۱. فایل عکس را در `public/images` آپلود کنید؛ مثلاً `taha.webp`.
۲. در `src/content.ts` مقدار `hero.photo` را از `''` به `'/images/taha.webp'` تغییر دهید.
۳. برای تصویر معرفی تیم از `about.photo` و برای نمونه‌کار از `work.items[].image` استفاده کنید.
۴. `photoAlt` و `alt` را متناسب با تصویر ویرایش کنید.

تا زمانی که مسیر عکس خالی باشد، جای تصویر عمداً با برچسب مشخص دیده می‌شود. عکس پرتره با نسبت تقریبی ۴:۵ و فضای کافی اطراف چهره مناسب است. نام فایل‌ها انگلیسی و بدون فاصله باشد. فایل بهینهٔ WebP یا JPEG ترجیح دارد؛ عکس‌ها و رضایت مشتری‌ها باید مجوز انتشار داشته باشند.

## محدوده و وضعیت نمونه

- بک‌اند، Supabase، ورود، پرداخت، خرید دوره، پنل و فرم ثبت درخواست ندارد.
- منوی موبایل و لینک بخش‌ها فعال‌اند؛ شماره تلفن و لینک‌های پیام‌رسان واقعی و قابل‌کلیک‌اند.
- لینک تلگرام براساس شماره ساخته شده و بازشدن حساب به تنظیمات کشف شمارهٔ گیرنده وابسته است. پس از دریافت آیدی رسمی، مقدار `contact.telegram` را جایگزین کنید.
- بخش نمونه‌کار فعلاً جای نگهدارنده است و هیچ نتیجه یا مشتری ساختگی نمایش داده نمی‌شود.
- آمار ۸۰۰ پروژه، ۱۱ سال و ۷۰ هزار نفر عمداً تا تأیید نهایی در صفحه نمایش داده نشده است.
- شعار بخش معرفی، متن پیشنهادی برند است و نقل‌قول مستند از طاها محسوب نمی‌شود؛ با او نهایی کنید.
- فونت Vazirmatn داخل build قرار می‌گیرد و در اجرا به Google Fonts نیاز ندارد.
- عنوان مرورگر و توضیحات موتور جست‌وجو در `index.html` هستند؛ در صورت تغییر نام/معرفی اصلی آن‌ها را هم تطبیق دهید.
- نمونه با `noindex,nofollow` ساخته شده تا قبل از تکمیل محتوا وارد نتایج جست‌وجو نشود. هنگام انتشار نهایی، متای robots را از `index.html` حذف کنید یا به `index,follow` تغییر دهید.

## GitHub و Codespaces

محتویات ZIP کامل را در ریشهٔ ریپازیتوری قرار دهید؛ `package.json` باید در ریشه باشد. سپس Codespace را باز کنید و دستورات بالا را اجرا کنید.

پس از پایان ویرایش جلسه:

```bash
git add src/content.ts public/images index.html
git commit -m "Update content after Taha meeting"
git push
```

اگر فایل دیگری را هم تغییر داده‌اید، آن را نیز به commit اضافه کنید. نسخهٔ جدید ریپازیتوری یا ZIP را برای ادامهٔ کار ارسال کنید تا تغییرات جلسه مبنای نسخهٔ بعد شوند.

## انتشار در Vercel

ریپازیتوری را در Vercel ایمپورت کنید:

| گزینه | مقدار |
|---|---|
| Framework Preset | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm ci` |
| Environment Variables | نیاز ندارد |

پس از اتصال GitHub به Vercel، push روی شاخهٔ متصل، انتشار جدید را آغاز می‌کند. تنظیم دامنهٔ `tahamansouri.com` را از بخش Domains انجام دهید و رکوردهای اعلام‌شدهٔ همان پنل را در Cloudflare وارد کنید.

## بستهٔ Changes Only

این اولین نسخه است، بنابراین فایل patch آن «از پروژهٔ خالی به نسخه 0.1.0» است و همهٔ فایل‌های اولیه را اضافه می‌کند. اگر ZIP کامل را استفاده کرده‌اید، patch این نسخه را دوباره اعمال نکنید.

برای نسخه‌های بعدی patch باید از آخرین نسخهٔ واقعی شما ساخته شود، مخصوصاً پس از ویرایش محتوا در جلسه. راهنمای بررسی و اعمال ایمن در بستهٔ Changes Only قرار دارد.

## قبل از انتشار عمومی

- عکس‌ها، خدمات و نمونه‌کارهای واقعی را کامل کنید.
- سه جلسهٔ رایگان، مقصد پیام‌رسان‌ها و شمارهٔ تماس را نهایی کنید.
- عنوان‌ها و ادعاهای محتوایی را با طاها تأیید کنید.
- `npm run build` را اجرا و صفحه را در موبایل مرور کنید.
- پس از حذف جای‌خالی‌ها، وضعیت robots را برای انتشار عمومی اصلاح کنید.
